# Plan: Catalog refactor (BACKLOG.md TODO)

## Goal

Make `catalog/major-minor-fingering.md` the sole RH fingering reference,
delete `catalog/README.md`, and rewrite `catalog/v1.ts` as a short,
prose-free data module — with the one resulting data correction (E-flat)
applied to `piano.db` via migration `0007`.

## Answers to the questions the BACKLOG item itself raises

**"Is there ANYTHING ELSE derived from v1.ts that is necessary in the
project?!"** — Only two files import `v1.ts`: `src/server/db/seed.ts` and
`tests/catalog.test.ts`. Everything else (exercises route, `create-run`,
`read-run`, backfill, the client) reads catalog data **from the database**,
not the file. What the project actually needs from `v1.ts`:

1. `ASCENDING_OFFSETS` — the W-W-H-W-W-W-H major shape (`[0,2,4,5,7,9,11,12]`)
2. The 12 keys' ascending note spellings (8 each)
3. The 12 keys' ascending fingerings (8 each)
4. Group slug/name/progressionOrder + each scale's
   slug/displayName/tonicPitchClass/positionInGroup — **byte-identical to
   current values**, because they're persisted in `piano.db` and seed-verified
5. `buildExercises` — descending = exact reverse of ascending (load-bearing:
   the validator enforces it, seed inserts both exercises from it)
6. `version: 'v1'` — kept only because the domain `Catalog` type requires it
   (nothing reads it)

Everything else in the file (provenance essays, per-scale reconciliation
comments, "alternate" fingerings) is deleted.

**"Best format to store those infos"** — keep a single slim TypeScript
module at `catalog/v1.ts`, structured as a flat 12-entry dict, exporting
`catalogV1: Catalog` unchanged. Rejected alternatives: JSON (no comments for
the justification paragraph, needs a schema/loader, drifts from the domain
types — and the never-created `catalog.schema.json` in ARCHITECTURE.md's
layout shows that path was already abandoned in practice); nested group
literals (a flat dict is shorter). TS keeps compile-time checking against
the domain `Catalog` type and zero import changes.

## The data (fidelity-checked against the md)

Per the one-octave rule (first seven fingers of the two-octave row, ending
on the higher of any `X/Y`), the 12 fingerings are:

| Scale | Ascending fingering | vs. current |
|---|---|---|
| C, G, D, A, E, B | 1-2-3-1-2-3-4-5 (1/5→5) | same |
| F | 1-2-3-4-1-2-3-4 (1/4→4) | same |
| B-flat | 2-1-2-3-1-2-3-4 | same |
| **E-flat** | **3**-1-2-3-4-1-2-3 | **changed (was 2-...)** |
| A-flat | 3-4-1-2-3-1-2-3 | same |
| D-flat | 2-3-1-2-3-4-1-2 | same |
| F-sharp/G-flat | 2-3-4-1-2-3-1-2 | same |

Descending stays the mechanical reverse (which automatically satisfies the
"start with the highest number in descending" rule, since reversal makes the
descending start equal the ascending end). Note spellings, slugs, display
names (with `fl`/`sh` unicode), pitch classes, group membership and
positions are unchanged.
